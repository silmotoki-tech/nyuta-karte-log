# メール/パスワード認証への展開手順

院内の稼働中端末を止めないため、**以下の順序を厳守**してください。  
順番を間違えると、全端末が一斉に Realtime Database へアクセスできなくなることがあります。

## なぜこの順番か

| 状態 | 旧端末（匿名ログインのまま・旧キャッシュ） | 新端末（ログイン画面入り） |
|------|------------------------------------------|----------------------------|
| 匿名認証が有効 & DBルールが従来どおり（`auth != null` 等） | これまで通り使える | メール/パスワードでログインすれば使える |
| 匿名認証を無効化したあと | **使えなくなる** | ログイン済みなら継続可 |
| UID 限定ルールをデプロイしたあと | **使えなくなる**（匿名 UID は拒否） | 院内共通アカウントの UID のみ可 |

コード側の新バージョンは匿名ログインを呼び出さなくなりますが、**Firebase コンソールで匿名認証を無効化するまで**、まだ旧キャッシュの端末は匿名で入れます。  
`database.rules.json`（UID 限定）も、**全端末のログイン完了までデプロイしない**でください。リポジトリに置いてあるだけでは本番ルールは変わりません。

## 手順（厳守）

### 1. Firebase コンソールで院内アカウントを用意する

1. Authentication → Sign-in method で **メール/パスワード** を有効化
2. 院内共通アカウントを **1つ** 作成（メール・パスワードは院内だけで管理。コードには書かない）
3. 作成したユーザーの **UID** を控える（後で `database.rules.json` に入れる）
4. **この時点では匿名認証を無効にしない**

### 2. ログイン画面入りのバージョンを push する

GitHub Pages / 配信先へ、メールログイン対応バージョンを公開する。

- この時点の本番 DB ルールは、従来の「ログイン済みなら可」（匿名も含む）のままにする
- リポジトリの `database.rules.json` は仮 UID のままコミットされていてよい（**まだ `firebase deploy` しない**）

### 3. 1台で動作確認する

1. PWA の「更新しますか？」バナーが出たら更新する（古い Service Worker のままにしない）
2. ログイン画面 → 院内アカウントでログイン
3. パスコード（2211）→ カルテ番号 → 記録の読み書き

問題があれば、全台展開前に止める。

### 4. 院内の全端末を更新し、1台ずつログインさせる

1. 各端末でアプリを開き、**更新バナーを必ず適用**する
2. 院内共通アカウントでログインする
3. パスコードを入力し、普段どおり使えることを確認する

共有 iPad では、アカウントのサインアウトは設定メニュー（⚙）からのみ可能です。  
誤操作防止のため、サインアウト時は管理者パスコード（マスタ削除と同じ）が必要です。

### 5. 全端末ログイン完了後に、初めて締め切る

1. Firebase コンソールで **匿名認証を無効化**
2. `database.rules.json` の `REPLACE_WITH_CLINIC_UID` を、手順1で控えた実 UID に置換
3. ルールをデプロイ:

```bash
# 初回のみ（未インストールなら）
npm install -g firebase-tools
firebase login

# このリポジトリのルートで（.firebaserc の default が nyuta-karte-log）
firebase deploy --only database
```

4. 1台で読み書きできること、未ログイン・別アカウントでは拒否されることを確認

## ルールファイルについて

- 置き場所: `database.rules.json`
- デプロイ設定: `firebase.json` / `.firebaserc`
- **データ本体はルール変更では消えません**（権限だけが変わります）

仮の内容（展開ステップ5までこのままでよい）:

```json
{
  "rules": {
    ".read": "auth != null && auth.uid === 'REPLACE_WITH_CLINIC_UID'",
    ".write": "auth != null && auth.uid === 'REPLACE_WITH_CLINIC_UID'"
  }
}
```

## ロールバック時の注意

- 新バージョンに更新済みの端末を旧バージョンに戻す場合も、PWA キャッシュの更新確認が必要です
- すでに UID 限定ルールをデプロイしたあとで匿名に戻す場合は、コンソールで匿名を再有効化し、ルールを従来形に戻すデプロイが必要です
