# 不具合・課題ログ

修正済みの不具合は「解決済み」に残し、対応方法まで書く（再発時の手がかりにするため）。
未対応は上から優先度順に並べる想定。着手・完了したら都度この場で更新する。

**このリストを更新するときは、過去の課題リストを書き写さず、必ず現在のコードと
突き合わせて判定すること。** 一度そうしなかったために、実装済みの項目が長く
「未対応」として残り、前提資料として誤った状態になったことがある。

## 未対応

- **旧右カラムのDOMを前提にした検証スクリプト**: `verify-med-exam-form-ui` /
  `verify-med-fields-restore` / `verify-med-freq-dose-balance` / `verify-disease-seed-ui` /
  `verify-history-master-ui` の5本が `#panel-meds` `#btn-med-add` などの旧DOMに依存して
  いる可能性がある。ただしフリーワード化で検証対象そのものが無くなったものも含まれるため、
  「直す」か「役目を終えたので削除する」かの仕分けが必要。
- **AI提案のファジーマッチング精度向上**: 保存直後のAI提案フローは `feature-flags.js` で
  オフのまま。再開するなら保存をブロックしない非同期通知型にする（`docs/decisions.md` 参照）。
- **検査のマルチセレクト**: フリーワード入力への転換により、そもそも必要かどうかから
  再検討が必要。
- **本番から外れた処置UIのコードとテストが残っている**: 検査・処置の統合（`ad59004`）で、
  `js/procedures-ui.js` と index.html 内の処置モーダルDOMは残したが、`app.js` からの
  初期化は外したため、ユーザーが到達できないコードになっている。`verify-procedure-plan.mjs`
  などの処置単体の検証スクリプトも、この到達できないコードを検証している状態。
  「削除する」か「統合後のUIを検証する形に書き換える」かの仕分けが必要。

## 解決済み

- **状態モードの既往歴に🟢が重複していた**（2026-09-17）: グループ見出しの🟢を外し、行末の
  「進行中／終了」と先頭の種別バッジだけを残した。キャッシュは `v210`。
- **状態モードの既往歴が編集できなかった**（2026-09-17）: 行タップの詳細を、新規追加と同じ
  フリーワード＋種別／状態のボタン選択にし、保存で一覧へ反映するようにした。メモは追記型を
  やめて1つのテキスト欄で上書きする。既存の複数メモは日付順に改行でつなぎ、内容は残す。
  キャッシュは `v209`。
- **状態モードの既往歴に削除手段が無かった**（2026-09-17）: 薬剤・検査・処置・特記と同じ
  `row-gestures.js` のスワイプ削除を既往歴行でも使えるようにした。削除専用の行は左右どちらに
  スワイプしてもゴミ箱が出る（左端カラムでは右スワイプが端末の戻る操作と衝突しやすいため）。
  確認ダイアログのあと一覧から消え、詳細モーダルからも削除できる。キャッシュは `v208`。
- **Service Worker のプリキャッシュ漏れ**（2026-09-11）: `js/app.js` から辿れるモジュールと
  `APP_SHELL_FILES` を突き合わせ、漏れていた `js/chip-detect.js` と `js/bulk-register-ui.js`
  を追加した。キャッシュは `v207`。`js/procedures-ui.js` は本番から外れているが、削除判断は
  別課題（未対応の「本番から外れた処置UI」）に残す。
- **検査と処置で予定の確認先が2箇所に割れていた**（2026-09-11）: 同じ列の上下に分けていた
  ブロックを「検査・処置」1つにまとめ、予定一覧・実施履歴一覧もそれぞれ1本にした。
  既存の処置データは `procedures/` を残したまま読み取り時にマージする。

- **認証の関門をパスコードのみで通過できた**（2026-08-11, `b690e65`）: パスコード一致だけで
  Firebase認証の状態を確認せず本編へ通していた。Firebase認証の完了確認を追加して解消。
- **匿名セッションを「ログイン済み」と誤認**（2026-08-11, `b90eadb`）: 端末に残った旧バージョンの
  匿名セッションを未ログインとして扱い、検出しだいサインアウトして必ずログイン画面を出すように
  変更。
- **verify-email-auth テストが不具合を検出できていなかった**（2026-08-11）: `js/auth.js` ごと
  モックしていたため、上記2件の不具合を両方素通りさせていた。Firebase SDKだけ差し替える
  `verify-auth-gate.mjs` を新設し、修正を戻すと検証が失敗することを確認する運用に変更。
  **教訓: 対象モジュール自体をモックするテストは不具合を捉えられない。**
- **ログインボタンが無反応に見えた**（2026-08-11, `b90eadb`）: `handleLogin` が `try` の外で
  例外を出すと `catch` に入らず無言で終了していた。全体を `try` で囲み、未捕捉エラーの安全網と
  エラーコード付きの画面表示を追加。
- **全文検索が検索タブに無かった**（Fableのレビュー指摘, 2026-08-10）: `chart-search-ui.js` として
  実装済み。現在は右カラム全体が検索＋AI質問の専用スペース。
- **マスタ検索が中項目名にヒットしない**（Fableのレビュー指摘）: 一度修正したのち、
  フリーワード入力への転換で階層マスタ選択自体が廃止されたため、課題として無効。
- **検査完了後に予定が消えて復活できなかった**（2026-08-21, `fe3a0b7`）: 完了時にまず予定を
  削除していたが、続く次回予定の入力画面で絶食が未選択のまま開くため、絶食必須の血液項目では
  保存がエラーで止まり、予定だけが失われていた。絶食を引き継ぐ（またはマスタ既定値を自動選択
  する）ようにし、あわせて「予定を削除してから作り直す」のをやめて既存の予定を更新する方式に
  変更。
- **予定1枚目のメモが編集できなかった**（2026-08-25, `eb1b8e2`）: 見た目は入力欄なのに実体は
  読み取り専用の表示だった。本物の入力欄に変更。あわせて実施履歴を開いたときに日付欄へ自動
  フォーカスしないようにした（iPadでキーボードが出なくなるのを避けるため）。
- **スワイプ削除のゴミ箱アイコンが本文に透けて見えた**（2026-08-15, `d42b433`）: 状態モードへ
  移植した際に前面の不透明背景の指定が漏れていた。加えてスワイプ終了の click が編集モーダルを
  開いてしまい二重に透けていたため、タップ処理も整理。
- **移行ボタンの進捗色が出ていなかった**（2026-08-15, `742fcea`）: JSがクラスを付け替えて
  いたのに、対応するCSSが未実装だった。
- **「肝スクリーニング」から重複したチップが出た**: 完全一致方式のため「肝スク」と
  「スクリーニング」の両方が検出されていた。あいまい照合への切り替え時（`58d8639`）に、
  重なる場合は開始位置が早く長い方を優先するよう解消。
- **中央・左カラムの表示フォーマット**: 日付＋見出しの2列構成、カテゴリ色の縦線、年グループ化と
  して実装済み。
- **マスタ階層選択の入力コストが高く、薬剤・検査がほぼ使われていなかった**: フリーワード入力＋
  サジェストに切り替えて解消（`docs/decisions.md` 参照）。
- **患者データの移行機能**: 中央カラムの「移行」（進捗3段階＋フリーメモ）と「一括登録」
  （貼り付けテキストから名前だけで登録）、カルテ番号の打ち間違いに備えた患者名検索として実装済み。
- **薬剤マスタの不足分**: 内服薬「その他」、処方注射薬・座薬、外用薬「シャンプー」を追加済み。
  ワクチン・狂犬病薬は実装予定なし。フードは端末でその都度追加する方針のため一括登録は不要。

## 採用しなかった指摘・提案

- **検査値の構造化（フローシート）**: Fableのレビューで提案されたが不採用。電子カルテ
  （anirece cloud）側の検査履歴の表がすでに使えるため、このアプリで重複して持つ必要はないと判断。
- **保存直後のAI自動提案フロー**: 精度・UIが安定せず、実装を一旦見送り。再開するなら
  保存をブロックしない非同期通知型にする。
- **薬剤の候補を「その患者の過去処方」から出す**: 新規登録時は「まだその患者にない薬」を
  入れる場面なので当てはまらないと判断。マスタ422件を候補元として使う。
